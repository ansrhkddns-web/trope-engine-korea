# Reference Synthesis Engine 2

Use this file when upgrading the skill from diverse cliche, motif, trope, folklore, web fiction, or story-ideation references. This is the second synthesis layer above the genre cliche banks.

The goal is not to copy reference examples. The goal is to turn reference material into Korean webnovel-ready cliche machinery.

## Source Families Used

| Source family | Useful idea | Webnovel conversion |
| --- | --- | --- |
| Trope catalogues | recognizable devices and audience signals | classify what readers recognize within 10 seconds |
| Tale type / motif indexes | large plot types vs small recurring motifs | separate premise engines from reusable motif cards |
| Propp-style functions | a cliche has a job in a sequence | convert a card into test, donor, aid, struggle, recognition, pursuit, or return |
| Dramatic situation lists | pressure comes from relationship conflict | attach a social or institutional pressure to flat ideas |
| Kishotenketsu / giseungjeongyeol | twist can come from recontextualization, not only direct conflict | use third-beat reversal to reveal the real rule, owner, witness, or value |
| Progression fantasy / LitRPG / xianxia discourse | growth is intentional, measurable, and repeatable | make power, skill, money, rank, or trust increase visible and staged |
| Korean regression / reincarnation / possession studies | death, restart, rebirth, and role transfer are desire codes | treat second chances as proof, agency, revenge, repair, and knowledge economies |
| Trope-based ideation research | tropes can be graph nodes | connect cliches as graph edges, not isolated labels |

## Seven-Step Reference Extraction

Apply this to any external reference, tag, trope, motif, or genre convention:

1. **Recognition signal**: What does the audience instantly recognize?
2. **Narrative function**: What job does it perform: test, aid, rescue, exposure, pursuit, recognition, temptation, reversal, return, or punishment?
3. **Pressure source**: Who or what forces the scene: timer, law, hierarchy, public accusation, contract, market, debt, taboo, disaster, desire, or rival?
4. **Korean webnovel institution**: Which local engine measures the result: association, guild, tower, system, constellation, chaebol family, board, sect, academy, court, market, media, household, or fandom?
5. **Proof object**: What makes the result visible: rank board, contract, recording, deed, item, scar, title, rescue footage, stock price, token, manual, apology, or changed access?
6. **Reader reward**: What is paid: power, money, status, revenge, knowledge, safety, relationship, recognition, autonomy, or justice?
7. **Renewal cost**: What problem the reward creates: debt, owner, pursuit, suspicion, changed timeline, taboo, tax, lawsuit, faction split, forced sponsorship, or moral debt?

If any step is missing, the reference is not yet a usable cliche card.

## Kishotenketsu-Compatible Cliche Loop

Use this when a cliche should feel fresh without adding a bigger fight.

1. **Gi / setup**: show a familiar genre promise.
2. **Seung / development**: let the protagonist pursue the expected reward.
3. **Jeon / turn**: reveal the reward's real category, owner, witness, metric, or cost.
4. **Gyeol / settlement**: pay the familiar reward while opening a new pressure.

Examples of safe turns:

- rank is not combat power but liability value;
- hidden class is not rare power but legal responsibility;
- auction item is not a weapon but evidence;
- death flag is not caused by the villain but by the rescue route;
- martial manual is not a technique but a contract;
- marriage contract is not romance protection but inheritance access.

## Progression-Compatible Cliche Loop

Use this for growth genres.

`method -> measurable proof -> public reclassification -> harder category -> method evolves`

The method must change or deepen every cycle. Do not repeat "numbers go up" without a new proof object or social consequence.

## Regression/Reincarnation/Possession Loop

Use this for second-chance or role-transfer genres.

`known script -> early choice -> visible deviation -> relationship/institution reaction -> future uncertainty`

The key is uncertainty. If knowledge remains perfect after repeated intervention, the story becomes bookkeeping.

## Trope Graph Rule

Treat cliches as graph nodes:

- **node**: a cliche card with role, reward, proof, and cost.
- **edge**: why one cliche causes or demands the next.
- **graph test**: remove one node. If nothing changes, that cliche is decorative.

Useful edge types:

- reward creates cost;
- proof creates witness;
- witness creates institution reaction;
- institution reaction creates antagonist;
- antagonist mirrors advantage;
- cost creates long-term engine;
- hook object changes owner.
