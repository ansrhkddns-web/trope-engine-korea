# Trope Portfolio Builder 5

Use this file with `cliche-selection-optimizer-5.md` when a request needs a ranked and balanced set of cliches rather than a long list. Phase 5 turns many candidate cliches into a compact engine portfolio.

## Portfolio Goal

A portfolio is the smallest set of cards that can deliver:

```text
click promise -> first proof -> social reaction -> new cost -> repeat method -> long-term hook
```

The goal is not to maximize novelty. The goal is to preserve a clear familiar promise while choosing enough variation that the first 5 episodes do not feel copied or flat.

## Portfolio Shapes

### 6-Card Quick Portfolio

Use for quick concepts.

| Slot | Job |
| --- | --- |
| identity | makes the click instantly recognizable |
| advantage | gives the protagonist an active method |
| proof | turns the promise into a visible first-scene result |
| witness | multiplies the reward through reaction |
| cost | makes success create the next problem |
| hook | opens the next episode or larger arena |

### 8-Card Commercial Portfolio

Use for most complete trope engines.

| Slot | Job |
| --- | --- |
| identity | reader recognizes the starting pleasure |
| advantage | protagonist can act differently from others |
| first proof | 1화 visible payoff |
| witness/social proof | someone with authority reacts |
| institution | the world changes its treatment of the protagonist |
| cost/antagonist | success creates pressure |
| renewal | episode 2-5 can repeat with variation |
| long-term hook | 50+ episode expansion arena |

### 12-Card Bible Portfolio

Use for bibles, 1-50 roadmaps, or multi-genre engines.

| Group | Cards |
| --- | --- |
| core promise | identity, advantage, reward metric |
| first arc | first proof, witness, cost, renewal |
| social engine | institution, rival, beneficiary |
| scale engine | antagonist ladder, secret arena, paid-boundary hook |

## Slot Requirements

Each selected card must do one primary job. It can have secondary effects, but never let a single card secretly cover everything.

| Slot | Must include | Fail sign |
| --- | --- | --- |
| identity | humiliation/deprivation/status gap or trapped role | generic "special protagonist" |
| advantage | actionable method or unfair information | passive destiny |
| proof | object, number, contract, result, duel, audit, rank, rescue, or public metric | private realization |
| witness | authority or emotionally meaningful observer | no reaction or random crowd |
| institution | rule, gatekeeper, hierarchy, market, school, sect, family, state, media | world does not respond |
| cost | consequence caused by the win | arbitrary punishment |
| renewal | repeat method with changed pressure | same face-slap again |
| long-term | larger arena connected to the first win | unrelated bigger villain |

## Genre Portfolio Presets

### Hunter/Gate

Core slots:

- identity: low-rank, support role, failed hunter, rejected scout, survivor;
- advantage: gate pattern memory, monster behavior reading, item appraisal, support skill reinterpretation;
- proof: rescue count, clear time, casualty reduction, raid log, artifact extraction;
- witness: association inspector, guild master, rescued party, broadcast, rival raid leader;
- cost: guild lawsuit, gate ownership dispute, monster adaptation, regulator audit;
- long-term: gate origin, national disaster board, illegal gate market.

- witness: floor administrator, rank board, constellation, challenger, audience channel;

## Portfolio Assembly Algorithm

1. Generate or collect 12-30 candidate cards.
2. Normalize each candidate using `cliche-selection-optimizer-5.md`.
3. Score every candidate.
4. Choose the highest `identity`, `advantage`, and `proof` that share the same reader promise.
5. Choose a witness that makes the proof public or socially meaningful.
6. Choose a cost created by the proof, not an unrelated danger.
7. Choose a renewal card that changes the next episode's pressure.
8. Choose a long-term card connected to the institution affected by the first proof.
9. Remove redundant cards and replace missing roles.
10. Convert the selected portfolio into first proof, 1-5 loop, and 50+ ladder.

## Balance Matrix

Use this after selection.

| Balance axis | Pass condition |
| --- | --- |
| role coverage | all required slots filled |
| reward variety | at least two reward channels, three for a bible |
| proof variety | first arc has at least two proof types |
| witness variety | private, institutional, and public/social witness are not all the same |
| cost integrity | at least one cost comes directly from success |
| agency | protagonist chooses method under pressure |
| repeatability | same method can face new pressure in episode 2-5 |
| originality safety | no unique setting/rule/scene chain copied |
| package alignment | title/logline/opening sell the same proof |
| scale continuity | long-term arena grows out of first institution reaction |

## Output Contract

For phase-5 outputs, include:

- brief and primary genre;
- source families used;
- candidate count and selected count;
- scoring table or top-candidate summary;
- final portfolio by slot;
- rejected/deferred cards with reason;
- first proof scene generated from the strongest proof card;
- 1-5 episode loop using the portfolio;
- 50+ expansion hook;
- validation verdict and first repair.

## Failure Modes

| Failure | Why it hurts | Fix |
| --- | --- | --- |
| top-score trap | high individual cards may duplicate each other | enforce slot coverage |
| novelty trap | fresh cards hide the genre promise | anchor identity/proof in familiar grammar |
| private payoff | readers cannot see the reward | add proof object and witness |
| free win | power has no pressure | make success trigger audit, lawsuit, duel, debt, rumor, or new rule |
| pileup | too many cards slow the first scene | cut to identity, pressure, action, proof, witness, cost |
| unsupported combination | support genre fights primary genre | make support genre provide cost or institution, not first click |
